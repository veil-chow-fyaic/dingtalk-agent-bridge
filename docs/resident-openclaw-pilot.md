# 把钉钉接到已有组织上下文的 OpenClaw

适用于已在 OpenClaw 使用其他消息渠道、希望让同一个 agent 处理钉钉工作的操作者。工作区中的说明、知识文件和被授权的工具可以共用。每个钉钉群、私聊及原渠道应有各自的会话记录和回复地址。在试点前确认哪些钉钉参与者可以使用该工作区的信息。

## 本次交付和版本

已发布的原生通道在 OpenClaw 2026.11.3 上通过真实模型及双路接收端文件验收。该次模型是通过本机服务运行的 Qwen3-14B。核心 bridge 可独立使用 CLI、HTTP 或持久 consumer。[文件样本与客户端核验](155-openclaw-two-route-file-acceptance.md) · [部署记录](156-native-channel-deployment.md)

E156 的插件声明宿主最低版本为 2026.11.3。阶段收尾还用 2026.7.1-2 的真实宿主加载器和隔离配置检查了旧版本，加载器报告版本不满足。单独导入入口并注册插件可以成功，这一步没有验证附件进入模型、回复路由或持久发送。旧宿主须依据兼容验证结果选择接入版本。[试点跟踪](https://github.com/veil-chow-fyaic/dingtalk-agent-bridge/issues/11)

## 试点顺序

1. 在实际服务启动的 profile 中核对宿主版本、已加载的通道、默认模型、会话绑定和目标工作区。用已经获准让钉钉参与者访问的组织资料，首轮选择一份合成样单。把真实机构名、群 ID、账号、原件和模型请求保存在本地。
2. 在隔离实例验证相同组织 agent 能回答钉钉任务，两条钉钉会话和原渠道各自有单独的会话键。使用针对新增钉钉账号的绑定。记录原渠道状态与配置摘要，给现有宿主安装经过审核的匹配版本。[插件安装与配置](../integrations/openclaw-channel/README.md)
3. 在固定截止核对历史水位、原消费者游标、在办任务和投递账本。单条路由一次仅由一个执行器领取新任务。已有不确定投递继续用原键对账，回退也须核对试点期间已执行的输入。[执行归属与回切](15-service-runbook.md)
4. 在已授权的钉钉私聊发一个新文件，要求按合成资料中的规则处理；追问一次，核对客户端收到的正文、原文件名和字节。群聊单独上传另一份文件，用 `/agent --files ["具体文件名"] 任务说明` 明确选件。两边使用不同的测试值，以便发现会话串用。
5. 验证新任务仅回原钉钉会话、旧渠道服务继续可用、取消后无迟到回复、受控恢复后无重复执行。记录每项是模拟、真实业务还是尚待观察。本试点的收件人是既有获准的钉钉会话，向微信转发消息属于另一项需求。

原生语音条出站继续暂缓，可用 WAV 文件；其余适配器与办公可选能力见[路线图](ROADMAP.md)。
