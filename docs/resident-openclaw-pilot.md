# 把钉钉接到已有组织上下文的 OpenClaw

适用于已在 OpenClaw 使用其他消息渠道、希望让同一个 agent 处理钉钉工作的操作者。工作区中的说明、知识文件和被授权的工具可以共用。每个钉钉群、私聊及原渠道应有各自的会话记录和回复地址。在试点前确认哪些钉钉参与者可以使用该工作区的信息。

## 本次交付和版本

已发布的原生通道在 OpenClaw 2026.11.3 上通过真实模型及双路接收端文件验收。核心 bridge 可独立使用 CLI、HTTP 或持久 consumer。[文件样本与客户端核验](155-openclaw-two-route-file-acceptance.md) · [部署记录](156-native-channel-deployment.md)

E156 的插件声明宿主最低版本为 2026.11.3。阶段收尾还用 2026.7.1-2 的真实宿主加载器和隔离配置检查了旧版本，加载器报告版本不满足。单独导入入口并注册插件可以成功，这一步没有验证附件进入模型、回复路由或持久发送。后续适配已在两版真实宿主、合成 DWS 和模型上验证组织工作区、双路附件读写、同会话追问、取消及重启防重。旧版主动发送缺少宿主持久投递 ID，文本与附件都会在调用钉钉前停止；可改用带固定幂等键的 bridge CLI。[试点跟踪](https://github.com/veil-chow-fyaic/dingtalk-agent-bridge/issues/11)

[双版本测试收据](../evidence/2026-11-19/openclaw-resident-sdk.json) 包含群聊与私聊的原件数、独立会话数、重启和取消计数。2026.11.3 在共享工作区并发写同一目录时曾出现一次宿主暂存错误；该版本的双路完整通过样本依次提交两个文件任务。两版均保留工作区文件访问限制。

## 现场验收

首轮 E159 试点中，既有组织 OpenClaw 分别独占原授权钉钉群与私聊的执行权。独立 transport 仍运行 E156 核对的 26 个核心模块（`d444ccf`）。宿主插件及其隔离的 Python 侧车来自 PR #13（`2388a04`）。原内置 gateway 的任务、会话绑定保留。

群聊和私聊分别提交一份合成文件。组织 Agent 在同一工作区用工具读取规则和各自的输入、写出结果，并分别回答第二轮追问。两路各有单独的宿主会话。收件客户端的两份结果文件均为 20 字节，名称及内容各自匹配。六笔投递都确认在原会话，正文保留宿主回复，客户端没有桥接调试前缀。

仅断开新增的钉钉通道后，两路执行锁释放，原有两个服务保持原 PID 和就绪状态。一条新私聊在此期间由 transport 入账，尚未被执行方领取。恢复原账号别名和同一 consumer 后，两个宿主会话 ID 保留；此前六个投递键均未重放，新私聊在客户端恰好收到一条回复。

随后完整切回原双路执行器。`fence`、`rollback-cut`、`rollback-plan`、`rollback`、`restore` 和 `restore-check` 六阶段均通过，复核了原两个 gateway 的执行程序、会话、试点期间的七条物理投递回执和 E154 的持久隔离。此次 `restore-check` 的执行归属为两个原 gateway。后续的再次接管和取消分别记录在 E160。 [E159 现场收据](../evidence/2026-11-19/openclaw-resident-live-pilot.json)

### 再次接管与运行中取消

E160 在完整回切后，使用新的具名消费者将群和私聊交回同一个组织 Agent、同一宿主账号。两个宿主会话 ID 与首轮相同。群和私聊各发一次新的独立追问，收件客户端分别得到各自原批次的正确答复。两笔新投递均在原会话确认，旧键没有重放。

同一发起人随后用 `/stop` 取消运行中的任务。模型在完成十次只读工具调用后确实中止；没有最终正文，观察期间没有迟到投递。控制消息记为 `done`，原任务仍为 `unknown`，账本中缺少两者的持久关联。原任务未重做，后续独立查询正常。当前严格回切会因这笔未解决的入站而拒绝切换执行权。E154 旧群正文仍按它的原发送键独立对账。

独立 transport 继续运行 `d444ccf` 的 26 个核心模块。磁盘已安装的插件 JS 0.2.1 与隔离 Python 侧车来自 `c1cf86e`。该次部署当时缺少运行中的 JS 版本证明。该版本的 577 项 Python 和 30 项 Node 测试通过；另在两版固定真实 SDK、合成 DWS 和模型上验证了取消关联、重启与新任务。原现场那笔未知仍保留。 [E160 现场与测试收据](../evidence/2026-11-19/openclaw-resident-reentry-and-cancel.json)

## 现场加载版本与本轮试用

在保留原微信服务及两条钉钉会话的情况下，仅重载了钉钉通道。宿主进程的启动日志报告插件 0.2.2、`native-cancel-v1` 和已检查的精确版本。两条路由由原具名消费者继续处理，原投递键和宿主会话 ID 保留。JS 发布文件来自 `12a17b4`，隔离 Python 侧车来自 `c1cf86e`，独立 transport 仍运行 `d444ccf`。

E161 完成安装时，桌面锁屏阻止了新任务的提交。E160 旧取消的运行内计数无法从留存记录重建，旧输入仍为未知，严格回切继续拒绝。 [E161 收据](../evidence/2026-11-19/openclaw-resident-release.json)

2026.7.1-2 会把源码包的可下载通道条目当作 npm 安装候选。0.2.2 移除这项元数据，通道继续由插件清单声明。隔离的真实旧宿主已从源码目录冷启动；现场使用宿主支持的热加载，两个原服务 PID 和就绪状态都已复核。两版真实 SDK 与合成后端均通过双路文件、重启、取消及后续独立任务。

### 群聊运行中取消

E162 在钉钉桌面解锁后完成。原发起人在群里提交一个只读任务，看到 GLM 开始读取合成文件后发送 `/agent cancel`。模型共完成十次读取，随后记录 `aborted`，没有生成最终正文。原任务记为 `canceled`，取消指令记为 `done`，通过新建的只读数据库连接查到了唯一的关联。宿主发送尝试和 I/O 错误均为零，核对时群里没有出现结果回复。

此前 E160 的私聊取消仍缺少持久关联，严格切回原执行器的检查仍会拒绝。两次任务各有独立记录。 [E162 现场收据](../evidence/2026-11-19/openclaw-resident-live-group-cancel.json)

## 试点顺序

1. 在实际服务启动的 profile 中核对宿主版本、已加载的通道、默认模型、会话绑定和目标工作区。用已经获准让钉钉参与者访问的组织资料，首轮选择一份合成样单。把真实机构名、群 ID、账号、原件和模型请求保存在本地。
2. 在隔离实例验证相同组织 agent 能回答钉钉任务，两条钉钉会话和原渠道各自有单独的会话键。使用针对新增钉钉账号的绑定。记录原渠道状态与配置摘要，给现有宿主安装经过审核的匹配版本。[插件安装与配置](../integrations/openclaw-channel/README.md)
3. 在固定截止核对历史水位、原消费者游标、在办任务和投递账本。单条路由一次仅由一个执行器领取新任务。已有不确定投递继续用原键对账，回退也须核对试点期间已执行的输入。[执行归属与回切](15-service-runbook.md)
4. 在已授权的钉钉私聊发一个新文件，要求按合成资料中的规则处理；追问一次，核对客户端收到的正文、原文件名和字节。群聊单独上传另一份文件，用 `/agent --files ["具体文件名"] 任务说明` 明确选件。两边使用不同的测试值，以便发现会话串用。
5. 验证新任务仅回原钉钉会话、旧渠道服务继续可用、取消后无迟到回复、受控恢复后无重复执行。记录每项是模拟、真实业务还是尚待观察。本试点的收件人是既有获准的钉钉会话，向微信转发消息属于另一项需求。

原生语音条出站继续暂缓，可用 WAV 文件；其余适配器与办公可选能力见[路线图](ROADMAP.md)。
