# 用户需求、交付现状与后续路线

## 本阶段交付范围

普通账号的独立 IM 工具与可选 OpenClaw 通道可在已验证的一个授权群和一个私聊中日常使用。两路均实测收发文字、图片、常用文件、WAV 和 MP4，交由真实模型处理，并在钉钉收件端按原名下载结果。正式模式由宿主决定回复内容，bridge 不添加诊断前缀或任务号。群聊可按命令、真实 @、每条消息或提示词判断参与。 [入门指南](getting-started.md) · [业务场景与群策略](agent-im-workflows.md)

E167 在原群从钉钉客户端交办一份新的 7 行库位盘点表。组织 OpenClaw 用自己的 `write` 工具生成补货清单，原群收到正文和 CSV。收件端下载后逐行复算，3 个库位共需 20 件，文件字节与宿主写入一致。 [本次收件验收](../evidence/2026-11-19/stage-delivery-inventory.json)

现场沿用 E156 独立 transport `d444ccf` 和 E166 的组织 OpenClaw 钉钉插件 0.2.5（源码 `5d1c09e`）。Agent 工具、权限和网络由宿主管理。一次临时 GitHub PR 查询触发了原生工具，现场 DNS 导致宿主在发出 HTTP 请求前拒绝访问。 [宿主工具收据](../evidence/2026-11-19/host-owned-tools-and-channel-boundary.json)

原 14 项 MUST 中 **13 项通过，R06 部分通过**。本阶段暂缓原生语音条出站。任意多个普通文件合为一个气泡、Hermes 与 DeepSeek Harness 端到端接入、多人和跨组织现场使用仍待验证。双路回切、恢复后续问及真实取消已有独立收据。 [原验收矩阵](../plans/completion/ACCEPTANCE_MATRIX.md) · [恢复与取消实测](resident-openclaw-pilot.md#再次接管与运行中取消)

## 产品初衷

普通账号、runtime和组织无关的钉钉IM工具：群/私聊双向文字与多媒体文件；CLI、HTTP和持久consumer独立，gateway按需接执行器。优先官方DWS的身份、通讯、历史、资源和办公接口，仅补路由、白名单、幂等、原件、队列、session与恢复。测试群不是产品固定组织，Kimi权限故障不阻塞通用IM。

原[PRD](../plans/completion/01-PRD.md)仍为14 MUST与3 SHOULD，17项ID/级别/判据与原始版本一致。R09要求至少一个执行器，已经满足；不新增四runtime全过门槛。

## 实际能力

| 用户要做的事 | 已实现和真实证据 | 明确边界 |
|---|---|---|
| 群/私聊收发文字与引用 | 双向文字、长文、换行、中文、emoji、重复正文、引用关系 | 私聊入站引用由E146补齐；按显式身份/路由隔离 |
| 收发常用文件 | TXT/CSV/PDF/DOCX/XLSX/ZIP代表性原件、客户端下载打开和SHA | 单个输出文件20MiB；不外推复杂宏/加密/所有格式 |
| 收发图片 | PNG/JPEG原生气泡、查看器、下载原件、真实处理 | 原生image≤2MiB，较大走file |
| 收发音频文件 | WAV群/私聊四方向原件、下载和播放器；有真实分析与官方听记样本 | 不等于聊天语音条；MP3/M4A和长录音未单独认证 |
| 收发视频文件 | MP4四方向原件、钉钉视频卡片/播放、下载和ffprobe/抽帧分析 | 约1秒H.264样本；独立video协议未验，不为标签另造通道 |
| 收取原生语音条 | E151 群聊 4.32 秒（11,674 字节）、私聊 3.68 秒（9,932 字节），两条 Ogg/Opus 单声道原件均完整解码、进入独立 consumer 的 ready 队列，并在钉钉客户端播放 | 真实样本限两条短录音，不外推其他编码、长语音或转写准确率 |
| 发出原生语音条 | 固定普通账号 DWS 尚无可用的新建入口 | 固定 DWS v1.0.67 的 `audio` 按文件发送。两路各转发原语音一次，都只得到文字 `[语音]`，资源数为 0，客户端没有播放控件。尚无可用的普通账号原生语音创建入口；发音频可用已验的 WAV 文件 |
| 多文件工具处理与回传 | E095群两附件实际Python工具/同群两结果/客户端下载打开，E017/E026私聊样本 | R07核心通过；不等于任意文件合在一个气泡或每个后续模型任务都成功 |
| 单条文字＋多图 | E134/E146 已核消息、图序和身份。E151 两路各有一条既有文字＋双 PNG 消息。从会话「文件」进入「图片及视频」，选中缩略图，在查看器中下载并保存，四张均从磁盘打开，按原发送顺序核对 SHA-256 一致 | 代码范围 1–9 张 PNG/JPEG，出站客户端实际验了每条双 PNG。任意多文件单气泡仍未实现 |

[四方向矩阵](../plans/completion/ACCEPTANCE_MATRIX.md)共 64 格，**54通过、6阻塞、4部分**。E151 两个入站语音格通过，两个出站多附件格部分通过。群、私聊的原生语音出站两格仍阻塞。

## 尚未完成

原 MUST 缺口为 **R06**。普通账号原生语音条出站在固定普通账号 DWS 中没有已确认的创建入口，实测转发未保留音频；可发送 WAV 文件。独立 video 协议四格仍未验，既有 MP4 视频卡片、播放和下载已验。多文件任务可逐件关联、逐件交付，任意多文件单气泡仍缺。

Kimi两次403的任务保持失败，无工具/结果，不重发、不换runtime绕过。OpenClaw原生通道E155双路真实文件已验；E154旧未知投递继续独立按原键处理，旧取消隔离的原始收据、Pi图片、跨组织多人和更多办公按独立证据推进。新的官方普通账号原生发送契约可用于重新评估 R06。

DWS最初Keychain直接失败点已定位，永久根因未知；桥接层有两并发/90秒+15秒清理/持久暂停。普通history错误可随正常轮询恢复，凭据/进程/清理故障不自动resume。UI截图临时ENOENT由补建目录恢复，与Keychain不是同一问题，目录消失原因未定。
