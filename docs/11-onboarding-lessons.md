# 接入步骤与踩坑经验

2026-11-13 E113重整为通用手册，不再把历史组织/账号/停机状态写成当前操作。最新部署证据见[E112](113-reboot-recovery-and-runtime-network.md)，认证故障的事实、未知根因、缓解措施和关闭条件统一见[风险清单](114-dws-risks-and-resolution.md)。旧全文与ONB历史条目可在Git的2065db6及此前版本追溯。

## 新环境接入顺序

1. 固定官方版本/来源/摘要，记录OS和runtime版本。项目v1.0.67与用户终端v1.0.61曾并存，不能凭`dws`名称假定执行同一文件。
2. 由目标组织管理员核“CLI访问管理”开通和人员范围；已有合适组织可直接使用，**不要求新建组织**。用户OAuth、桌面登录、组织授权和具体资源权限是四件事。[固定官方开通说明](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli/blob/v1.0.67/README_zh.md)
3. 操作者在自己的设备完成官方登录；不分发本机token或复制登录目录。新设备登录不是本机助手重新做认证诊断的许可，本机仍禁止auth/doctor/Keychain操作。
4. 在私有配置中固定profile/发送者/精确会话。会话搜索可能模糊匹配，不能取第一项猜群；产品不绑定本次测试组织。桌面veil和DWS liev是两个真人账号，`[Agent]`只是文字，UI另显示“通过AI发送”。
5. 在明确授权的专用测试范围依次核只读历史、一次合成发送、原key回执、实际另一端UI、文件原件下载打开；分开文字、图片、音视频文件和原生协议。当前现场只准AIC及原私聊，不去企业大群试功能。
6. 最后才接任务执行器，验证原session、真实工具、状态/取消、新会话与同会话交付；接入成功后继续记录自然运行、维护和刷新证据，不能一次成功就承诺长期稳定。

## 直接复用的经验

| 编号 | 踩过的坑 | 正确做法/验证依据 |
|---|---|---|
| L01 身份和权限分层 | 桌面登录不代表DWS同账号已授权；普通账号不等于所有桌面权限 | 明确组织开通、OAuth、显式profile、目标会话与具体API。每个新组织独立核验，不复制旧ID/默认账号 |
| L02 退出码和进程状态 | auth status曾exit0但authenticated=false；HTTP202、进程running、slot released也不能证明送达 | 业务状态、官方回执、真实工具终态、用户UI、下载摘要分别验证；不把工具文字中的messageId当凭据。E102/E108/E112 |
| L03 参数是每个命令自己的契约 | 强加通用--as导致一次获准查询在参数解析阶段失败 | 对固定命令声明树验证，不照其他命令或旧Help猜参数。E082/E083原失败保留 |
| L04 消息类型与文件形态 | WAV/MP4作为file可播放，但未证明原生语音/video；JPEG文件名可能被客户端追加.png | 核原协议类型、内容字节、显示与原件，不凭后缀或播放器通过升级结论。E029/E098 |
| L05 单消息附件组合 | 重复--file只留末项；客户端多选常拆成多消息；正文/file互斥 | E056官方契约边界保留；群以--files明确关联已观察附件，私聊按已验关联，不把分条合并当单消息多附件 |
| L06 超时后的副作用未知 | 官方请求超时仍可能已发送；切UI或换key会重复 | 先持久保留，再按原key/task对账；没有回执不猜成功/失败，不自动重做任务。E052/E102 |
| L07 文件在排队后变化 | 只校路径不够，产物可被后续任务覆盖 | 冻结SHA/字节数/目标；发送前校验，坏缓存明确失败，显式repair到新目录保留旧证据。CEO C01/E093 |
| L08 history分页与恢复门槛 | 忽略nextPageToken会永久积压；last_sync.at是调用开始，不是覆盖完成 | 持久原窗口/游标；同一SQLite快照watermark≥固定cut且无history_window，gateway停机核积压。E084/E109纠偏/E112 |
| L09 “退出0”不是Agent完成 | 非终态输出/错session不能交付；工具输出429不等于provider限流 | 能力声明、可信terminal、会话协议指纹和错误类别分开；不兼容需明确迁移或新会话，旧历史不清空。CEO C03/C04、E104/E109 |
| L10 取消/崩溃后遗留工具 | 只杀父进程可留下工具继续写；后台重启可能重做 | 同组清理及父死亡守护，失败/未知不重放；不宣称恶意脱组隔离或外部效果回滚。E045–E047 |
| L11 DWS共享bus不归本实例独占 | 官方Stream bus独立Setsid，退出consumer并不等于bus应被杀；foreground并非personal消费者修复 | 当前history-only，不杀共享bus、不随便加flag绕开生命周期。E073 |
| L12 错把所有故障当登录坏了 | Keychain存储、DWS上游超时、bridge暂停、Kimi OAuth网络、UI图像失败实际不同 | 用[D01–D09](114-dws-risks-and-resolution.md)分类；禁止login/doctor轮询、反复密码或锁/解锁。这次事故处置放大弹窗是我们的错误 |
| L13 系统代理不等于子进程代理 | 桌面有代理，gateway无环境变量；Kimi OAuth超时，DWS仍可收发 | E112继承已有代理后真实成功；E115/E116已补持久配置/无代理manager重启及两路UI，不把网络探针成功当Kimi成功或根因证明 |
| L14 UI与真实用户观察 | 发送API成功/本地文件存在不等于对端看到并下载；旧坐标会失效 | 先取当前UI，veil真实交办/liev回复；从钉钉下载再打开与SHA比对。前台变动重读；同失败路径两轮无新证据停 |

## 不能再拿来当“解决方案”的动作

自动重登录、周期性doctor、反复读/锁/解锁钥匙串、删除旧凭据、file-DEK降级、复制token、杀系统守护、放宽权限、盲目扩大超时、无条件升级或换账号/bot。当前不存在已证明根治系统故障的一键操作；失败时先停新增调用、保留归属和账本，按风险分类处理。

用户曾自行新终端登录成功、又自行重启后恢复，是有效事实；不是要求其他用户每天这样做的操作手册。上游明确修复、产品补丁、缓解和恢复应分别标状态。

每次新经验记录版本/触发/观察/已排除/处理/验证/未知/下一证据。原始账号、聊天、截图和凭据只留local；只提交脱敏结论、合成fixture及许可。新设备最终交接还须当前版本干净安装和真实专用会话验收，不能拿历史包凑完整交付。

## E115/E116：不要依赖临时启动环境

macOS系统代理与CLI继承的HTTP(S)_PROXY不是同一个事实。已验证的网络条件要保存到私有runtime.environment，让无代理manager重启后仍能传到实际CLI/工具；不将本机地址作为产品默认、不改HOME或复制凭据。环境配置改变不需要清空原会话。

DWS的released只证明调用槽释放；result诊断需另保留安全category/reason/exit/耗时/阶段，而最终投递仍看回执和用户UI。未知提供方值不能原样写日志，也不能遮蔽已知reason。日志写失败不能把成功发送变成待重发。历史缺原信封就保留未知，不事后补造根因。

本轮86旧任务保持，部署后两路真实Python、文件下载/Quick Look与摘要通过；没有改认证或钥匙串。[完整记录](116-persistent-environment-deployment-ui.md)。

## E117：取消必须传至真正的子进程

仅外层select超时不能结束底层exec.Command；预算需从预检查开始，逐层传context，成功Start之后必须Wait回收。清理期耗尽就保留pending，不把返回错误等同进程已退出。原写入已发生的副作用不能靠取消回滚。候选只用固定源码/合成进程验证，未改官方binary或真实存储；[候选与限制](117-dws-cancellation-candidate.md)。系统-25293与该取消缺口不能混为同一根因。
