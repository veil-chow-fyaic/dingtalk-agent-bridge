## 当前使用谁的身份

本机钉钉 UI 登录名是周威。当前 bridge 明确调用 `chat +messages-send --as user`，使用已授权真人账号；没有创建独立机器人。`[Agent]` 是输出文本前缀，不是钉钉账号或 bot 身份。

本轮 UI 实际看到：任务和回复都在本人右侧，Agent 输出带“通过 AI 发送”标签。DWS Help 的 `--ai-tag` 默认 true，与客户端呈现一致。UI 发出的任务和三个 Agent 回复，在服务端具有相同稳定 sender ID，也与绑定账号一致。

因此当前体验是“本人在会话中发显式命令，自动化以本人身份补充回复”，而不是“本人私聊一个独立 Agent 联系人”。这两个产品形态必须区分。需要独立联系人形态时，可选择独立真人执行账号或 bot；bot 路线已有官方 `dev connect` / Connector，仍需独立身份和覆盖验收，不能靠更改文本前缀实现。

## 本轮实际 UI 操作

1. 使用原生 UI 自动化打开钉钉，核对登录菜单中的周威、原内部群标题与成员数。
2. 在原群输入框填写并点击发送：`/agent [DAB-UI-GROUP-001]`，要求计算37×19，生成TXT并回群。本次输入不调用DWS发送接口。
3. 在客户端看到任务气泡、接收回执以及 `37 × 19 = 703` 的文字结果。
4. 在客户端看到 `0-ui-group-check.txt` 文件卡片，点击下载，经系统保存对话框保存到本次验收目录。
5. 从文件卡片点击打开，TextEdit窗口显示 `DAB-UI-GROUP-001` 和 `37 × 19 = 703`。
6. 对通过客户端下载的32字节文件进行摘要校验，与Agent生成/暂存件一致。

这次通过的是原群的“UI输入→实际Kimi执行→UI可见文字/文件→客户端下载→打开内容”链路。发送时群成员1；随后UI出现liev加入、成员2。助手没有邀请、审批或自动给新成员执行权限。

## 私聊的准确状态

当前真实配置只有一个group路由，没有direct路由。代码支持direct且有自动测试，不能写成当前私聊部署可用。UI已核对现有“我（周威）”会话，输入框提示可向自己发送文件；这是本人会话，不是独立对端。

用户最新要求已恢复群聊/私聊UI验收，旧“私聊全部暂跳过”不再作为本轮停止理由。独立私聊接收人尚待用户给出准确测试名称；不能随意选择侧栏业务联系人，也不能把自己发给自己算作人与人私聊通过。当前此项仍为未通过，不以群内成功代替。

## DWS 已确认与尚未确认

- 已确认当前固定版的user/bot/webhook发送身份分支、user身份回执与历史/资源路径、默认AI标记，以及本轮UI实际呈现。
- 已确认官方dev connect入口与教程，但本项目未创建机器人、未完成bot身份的群聊/私聊UI闭环。
- 已验证有限业务路径，不代表已摸清DWS所有产品、所有会话类型、所有权限与异常。
- 私聊的独立对端、他人入站、外部会话、完整Stream业务接收和原生音视频仍需逐项实测。
