## 实际发现及修正

1. 旧版不支持本地图片到内联资源的结论仅适用于 v1.0.61。v1.0.67 已提供 `chat +messages-send --markdown` 中的本地图片路径处理（reply 的正文参数为 --content，不能混传），必须独立验证版本，不能过早决定 AX。
2. v1.0.67 某些命令增加 `{ok,outcome,data,meta}`，其他 shortcut 仍返回各自 contract。适配层只针对 outcome 外层解包，不对所有 data 盲目解包。
3. 仍需保留原任务 ID：重复 key 返回冲突，本地账本能让业务重试取得原结果，避免上游冲突影响 Agent。
4. 读取完整度与发送回执分离；消息后来进入历史的情况通过后续补读进入账本。不会将调用成功理解为立即可查所有历史。
5. 本机 AX 只读观察到测试群归属于新组织且成员 1，同时桌面显示“网络连接已断开”。旧 WAV/MP4 可见为下载文件。未更改网络/安全设置、未重启客户端；新版图片 UI 呈现标为待验证。DWS 在此期间仍可进行服务端读写。

## 该阶段验收结论

单人、指定内部群范围下，文本、文件和新版内联图片的官方 API 路径，以及文档/待办代表性办公操作通过；提供可运行的实验服务。不是完整生产验收：其他人入站、普通群不 @ 接收、私聊、外部会话、原生音视频、客户端新版图片呈现、24/72 小时稳定性尚未通过。

已经做完的实验不再重发作为下一轮开场。后续开发基于真实剩余缺口，而非重新搭环境。用户明确跳过的多人部分保持 skipped_by_user；该阶段图片 UI 未测，现已由 docs/20 补齐本机多图呈现。没有要求用户现在邀请成员或重复授权。
