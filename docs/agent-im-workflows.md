# 从钉钉给 Agent 交办工作

## 消息补全、故障和顺序

群聊或私聊的临时轮询故障独立退避。群参与判断读取最多 8,192 个 Unicode 码点的完整正文；更长时保留首尾各 4,096 个并标出省略处。自然追问可以引用同一路通道已确认投递的纯文字。接收文件仍须从消息资源中获取原件。

DWS 首次只返回截断内容时，桥保留原消息。后来收到身份、会话和创建时间一致的完整投影后，持久 consumer 在原序号处更新。主动跳过的历史和已执行的任务仍保留原处理结果。DWS 必须在可见历史中实际返回完整条目。可选 gateway 依据归档边界处理迟到输入。OpenClaw 匹配停止请求时核对原序、发起人和可证实的创建时间。OpenClaw 在外部重建同一个会话键时，通道能使用的关联信息限于宿主提供的标识。 [E168 文件验收与回归](../evidence/2026-11-20/im-review-fixes.json)

私聊可直接提问。群聊默认用 `/agent` 发起任务，管理员也可以为这个群选择真实 @、每条参与，或让组织 Agent 按提示词决定是否答复。

## 连发消息、原件与智能群

每条消息保留自己的入站记录。普通私聊按序进入同一会话，一条消息里的图片和文件按原顺序交给宿主。跨消息的一项明确任务可用 `/agent --attachments [{"image":1},"清单.tsv"] 核对标签主色和清单批次`。图片序号按指令之前本人发送的原图倒序计算。智能群中，单独上传的资料可以保持静默，后续中文或英文的常见“刚才那张图”指代可以关联两分钟内八条消息中的唯一原件。遇到多个候选或他人上传时，群内会收到引用或显式选择提示。

群策略可逐群设置为 `command`、`mention`、`always` 或 `agent-decides`。智能模式的第一步使用组织模型进行无工具判断；决定回复后，才将任务交给原有 Agent 与其工具。明确静默会留原因；模型超时或输出无效会等待重试，同发送者的后续任务保持顺序。未知执行或投递保留原记录。严格 @ 依赖官方提及索引可见，手打显示名不会触发。

组织 GLM 在原群对收悉、两条独立上传及答复后的致谢共四次静默。群和私聊分别读出实际图片主色和各自 TSV 的批次号。群里同一份图片的精确像素宽高未能由当前组织工具核验，客户端收到了明确说明。在隔离环境中，本地 Qwen 配有读 PNG 文件头的工具，读出了像素尺寸；即使提供了已答回执，它也曾对后续的资料图重复上一问的答案。 [E165 现场收据](../evidence/2026-11-19/openclaw-group-tools-and-mixed-media.json)

## 组织宿主的知识、记忆和技能

真实群聊中的新同事问题没有给出答案。宿主记录显示已注入身份文件，GLM 的回答包含三个约定呼叫名，与源文件一致，钉钉收件端看到相同正文。该轮没有发起工具调用。

另外两次交办分别是私聊查询一条试点前的历史日记，以及群聊用 Agent Reach 核实公开 PR。当时组织宿主收到 SIGTERM 并正常退出。独立 bridge 已保存两条输入。原有服务恢复后，消费者分别领取并执行两条原消息，原私聊和原群各收到一次回复。停止与恢复的发起方未知。

该宿主的技能目录向钉钉会话列出了 Agent Reach；当时报告的工具包含 `web_fetch`、`memory_search` 和 `memory_get`。现有 `agent_reach` 工具由另一渠道的插件注册，注册代码仅对其自身渠道返回工具。插件的技能目录、可执行工具和成功读取公开网站需分别验证。 [本轮收据](../evidence/2026-11-19/openclaw-user-workflows.json)

### 真实用户最后拿到了什么

- **查旧记录。** GLM 在私聊调用原生 `memory_search`。检索摘要命中了试点前的原始日期笔记，足以回答记录日期、原因和当天的处理方式。三个事实及引用的日期均已核对。
- **查 GitHub。** GLM 读到技能说明后，分别尝试了 GitHub 网页和官方 API。两次 `web_fetch` 都返回目标解析为私有、内部或特殊用途地址的拒绝。收件方收到失败说明。E165 用 0.2.4 的临时桥内工具读到了预同步的 #17。0.2.5 已移除该工具和采集脚本。E166 从钉钉临时询问未同步的 `cli/cli#15086`，宿主在 GitHub 网页及 API 上均遇到相同拒绝。独立官方核对与宿主实际回答分别记入收据。 [现场收据](../evidence/2026-11-19/host-owned-tools-and-channel-boundary.json)
- **按技能做判断。** 私聊交办三条工单后，GLM 再次读取安装的技能说明。关于字幕是否完整、限流等待时间以及由谁处理平台验证的意见均与手册一致。回复多了一行标题。
- **修订并交付文件。** 沿用同一私聊的结果，用户要求把三条判断整理成可导入的 TSV。GLM 实际调用 `write`，文件卡片与说明均确认在原私聊投递一次。钉钉客户端下载的文件名称正确，UTF-8 内容为四行两列（含表头），494 字节与宿主原件逐字节一致。 [现场回执与范围](../evidence/2026-11-19/openclaw-user-workflows.json)

## 真实本地模型如何执行技能

在独立的合成组织里，本地 Qwen3-14B 通过真实 OpenClaw 2026.11.3 处理了两组交办。两次私聊都读到了旧日记中的原因码和补救码。两次询问未记录的政策期限都回答未记录。模拟钉钉接收端收到六条回执，正文逐字匹配模型终稿，群聊和私聊各自返回。

两个技能结果暴露了业务风险。开放读写工具的那一轮算对了交接码，但多写了解释，而且自行重写了合成技能文件，去掉了末尾换行。只读配置保住了文件原件；模型用真实 `skills_read` 取得完整规则，却算错了结果。这两次测试都验证了技能进入模型与原路交付，精确业务输出各有失败。 [分项收据](../evidence/2026-11-19/openclaw-user-workflows.json)

独立的新工单用一个确定性只读工具计算交接码。真实 Qwen 首次传错库区，被工具拒绝；它读取技能说明，在同一任务内修正参数，取得与独立复算一致的结果，原合成群恰好收到一条准确回复。技能文件字节保持一致。这一组验证了宿主工具可以对精确计算承担责任。

## 在隔离环境复验

给一份已构建、版本和提交均匹配的 OpenClaw SDK 源码目录运行以下命令。探针生成独立群聊、私聊、工作区和随机规则，使用本地合成模型与模拟 DWS。两版固定 SDK 都从真实系统提示读取了组织身份，调用 SDK 的 `read` 读取旧日期笔记，从宿主技能目录定位 `SKILL.md` 并按规则生成用户指定箱号的标签，各自向原会话交付三次。

```sh
python3 scripts/probe_openclaw_native_channel.py /path/to/built/openclaw --workspace-context
```

再加 `--native-memory` 可测试不提供日期、路径或答案的旧记忆问题。两版真实 SDK 都调用原生 `memory_search` 从三份笔记里找到目标，用 `memory_get` 按返回的路径和行号取得随机答案。此模式使用 SQLite 关键词检索，未测试向量语义召回。
